# Форматы топологии трасс: JNC, EDG и MAP

В этом документе зафиксированы результаты реверс-инжиниринга структур топологии дорожного полотна из исполняемого файла `nfs5.exe` (адреса VA `0x48789f`, `0x481080`, `0x488090`, `0x487e80`, `0x485100`, `0x440ee0`).

Исходные файлы игры находятся в `local/game/GameData/Track` и в Git не добавляются.

**Уточнение 2026-09-23, аудит 005:** размеры записей и чтение полей подтверждаются
локальными ресурсами/дизассемблированием; семантика флагов `.edg` ниже остаётся
гипотезой, а не установленной классификацией покрытия. Коэффициенты сцепления
из этих значений пока выводить нельзя. Роль `.jnc` в контрольных точках круга
не подтверждена. VA `0x440ee0` не подтверждён как начало MAP-парсера:
линейное декодирование начинается внутри инструкции. См.
[аудит 005](../iterations/005-unified-driving/research/topology-evidence.md).

## 1. Файлы `.jnc` (Junctions — соединения и развилки дорог)

- **Загрузчик в `nfs5.exe`**: функция `0x48789f` вызывает `0x481080(manager, "%s.jnc")`.
- **Проверка размера**: размер файла делится на 36 (`0x24`) с помощью умножения на константу `0x38e38e39` и сдвига вправо на 3 бита. Число записей строго сверяется с количеством узлов развилок трассы (`cmp esi, edx; jne error`).
- **Размер записи**: ровно **36 байт** (`0x24`):
  * `u32 index` — 0-based индекс развилки (`0, 1, 2...`).
  * `f32 weights[8]` — до 8 весов/вероятностей выбора направления движения на развилке (например, на развилке с двумя дорогами на `alps.jnc`: `1.0, 0.15, 0.85...` — 15% и 85%).
- Все 15 файлов `.jnc` игры строго кратны 36 байтам:
  * `skidpad.jnc`: 36 байт (1 запись)
  * `alps.jnc`: 216 байт (6 записей)
  * `autobahn.jnc`: 1260 байт (35 записей)
  * `canyon.jnc`: 612 байт (17 записей)
  * `castle.jnc`: 864 байт (24 записи)
  * `coastal.jnc`: 216 байт (6 записей)
  * `farmland.jnc`: 504 байт (14 записей)
  * `foothills.jnc`: 216 байт (6 записей)
  * `forest.jnc`: 216 байт (6 записей)
  * `industrial.jnc`: 936 байт (26 записей)
  * `monaco1.jnc`: 144 байт (4 записи)
  * `monaco2.jnc`: 216 байт (6 записей)
  * `monaco3.jnc`: 396 байт (11 записей)
  * `monaco4.jnc`: 360 байт (10 записей)
  * `monaco5.jnc`: 216 байт (6 записей)

## 2. Файлы `.edg` (Road Edges — границы и кромки дорожного полотна)

- **Загрузчик в `nfs5.exe`**: функция `0x488090` вызывает `0x487e80(path)`.
- **Проверка размера**: вычисляется по формуле `(file_size - 4) / 28` с помощью обратного умножения `0x24924925` и битовых сдвигов.
- **Заголовок**: 4 байта (контрольное значение / CRC / версия). Пропускается загрузчиком (`sub ecx, 4`).
- **Размер записи**: ровно **28 байт** (`0x1c`):
  * `u8 flags` — байт атрибутов (читается как `movzx cx, byte ptr [esi - 8]`); следующие значения — прежние, ещё не доказанные гипотезы:
    - `0x00` — обычная кромка дороги (асфальт/обочина)
    - `0x10` — барьер / отбойник / бетонная стена
    - `0x20` — бордюр / поребрик / трава
    - `0x30`, `0x50`, `0x60` — специальные кромки разделителей и тоннелей
  * `u8 padding[3]` — 3 неиспользуемых байта выравнивания записи.
  * `[f32; 3] p1` — 3D-координаты `[X, Y, Z]` начала отрезка (в метрах).
  * `[f32; 3] p2` — 3D-координаты `[X, Y, Z]` конца отрезка (в метрах).
- **Система координат**: оригинальные координаты `p1` и `p2` при загрузке в Scene преобразуются по правилу `[x, y, -z]`.
- **Геометрическая структура**:
  * Отрезки соединяются последовательно (`p2` предыдущего совпадает с `p1` следующего), образуя левые и правые границы полотна дороги.
  * На `skidpad.edg` 167 записей формируют замкнутый круговой контур радиуса ~240 м.
  * На сложных треках (`alps.edg` — 7694 записей, `autobahn.edg` — 10555 записей) границы описывают многополосные участки, съезды, мосты и развязки.
- Все 15 файлов `.edg` в игре удовлетворяют формуле `(size - 4) % 28 == 0`.

## 3. Файлы `.map` (Sections & Texture Mapping)

- **Формат**: текстовый INI-файл; прежняя атрибуция парсера VA `0x440ee0` требует восстановления границ функции и проверки xrefs.
- **Секция `[header]`**:
  * `tint` (4 `f32`) — оттенок освещения
  * `ambient` (4 `f32`) — фоновое рассеянное освещение
  * `interior` (4 `f32`) — параметры освещения салона
  * `lightdecal`, `interiordiffuse` — дополнительные параметры света
- **Секции `[sectionN]`**:
  * `startslice`, `endslice` — диапазон срезов дорожного полотна.
  * `texture1.open`, `texture1.covered`, `texture2.open` — FourCC-идентификаторы текстур из архива FSH трассы.
  * `texturesize` (`f32`, по умолчанию `6.0f`) — масштаб наложения текстуры.
  * `aspect` (`f32`, по умолчанию `1.0f`) — соотношение сторон текстурного тайла.
