# 002-track-viewer — следующий этап

Статус 2026-09-19: запланирован, реализация не начата. Основа — принятый
снимок `iteration-001`; ресурсы только из общего read-only `local/game`.
Опорный коммит: `b58ee17`. Активных исполнителей нет. Этот документ — план 002,
пока её папка не создана; при старте перенести задачи в её собственный PLAN.md.
Уровни моделей ниже относительные: подходят любые провайдеры и локальные модели,
если их возможностей достаточно. Роли не требуют конкретных model ID или API.

## Цель

Загрузить и показать один реальный участок трассы с исходной геометрией,
размещением и текстурами в native/WASM. Сначала установить фактические форматы
и связи ресурсов; не подменять неизвестные данные заглушками.
Участок должен позволять проверить дорожную поверхность, стык соседних
геометрических фрагментов и хотя бы один объект окружения, если он есть в ресурсе.
Первый этап не обещает поддержку всех трасс. Проверяемый ресурс выбирается после
инвентаризации; расширения файлов, координаты и единицы пока не установлены.

## Задачи и точки приёмки

Все задачи ниже ожидают старта. Названия новых файлов — предлагаемые места
владения, не утверждение, что эти файлы уже существуют.

- Приёмка координатором: ресурс реально существует, набор доступен, выбранный
  участок достаточно мал для быстрой проверки и содержит нужные элементы.

### T02 — снимок и контракт (координатор; после T01)

### T03 — формат и сборка ресурсов (средний исполнитель / formats; после T02)

- Владение: новые модули nfs-formats/src/track*.rs,
  nfs-assets/src/track*.rs и документация формата внутри 002.
- Сначала один блок/объект и связь с текстурой; затем соседние фрагменты.
- Проверить границы, переполнения, индексы, размеры выделений, конечность координат;
  неизвестные обязательные поля не заменять нулём или фиктивным треугольником.
- Установить масштаб/оси/размещение и winding по данным; старое правило CRP /5
  не переносить на трассу без доказательства. Reference-код не равен доказательству EXE.
- Приёмка: численный inspect, bounds/счётчики, необходимые текстуры найдены;
  parser tests на валидных, обрезанных и некорректных данных.
- Простые тесты по уже установленной схеме можно отдельно дать лёгкому исполнителю:

### T04 — отображение (renderer; после T03)

- Проверить текстуры, culling, alpha/depth и соседние фрагменты в GPU.

## Политика расхода лимита

Использовать [общие правила агентов](agents.md). Координатору не выполнять массовую
инвентаризацию или типовой код вместо доступного простого исполнителя, но и
не тратить отдельный запуск на однострочную правку. Обычно 1–2 агента:
T03 + T05, затем T04 + T05. T01/T02/T06 принимаются последовательно.

На поручение: ID, ожидаемый артефакт, 1–3 нужных пути, разрешённые файлы,
проверка и стоп-условие. Две неудачные попытки по одной гипотезе — разбор
координатором, а не новый такой же агент. Повышать модель для конкретного
нерешённого вопроса, не для всей оставшейся итерации. Финал исполнителя <=8 строк.

В PLAN 002 вести для каждой T-задачи состояние pending/active/verified/blocked,
фактического владельца, артефакт проверки и ближайшее действие. На передачу сессии
убирать завершённые назначения и сохранять воспроизводимую команду для блокера.

## Готовность

- Реальный участок, без выдуманной геометрии; видимые стыки/текстуры проверены.
- Ошибки ресурсов диагностируются с именем и смещением, без падений/выхода за границы.
- Парсерные тесты, native/WASM сборки, GPU-снимки и браузерная проверка.
- Автомобильная загрузка и тесты 001 не регрессируют.
- README/PLAN/STATUS актуальны, run содержит точные команды и наблюдения.
- Измерены размер входных данных, число объектов/треугольников, время загрузки
  и известные ограничения памяти; численные бюджеты назначить после T01, не выдумывать.

Не входит: физика, AI, гонка, полные CLR-палитры, все варианты повреждений/анимаций.
Native UI smoke из ограничений 001 проверить при доступном desktop connector.

Ближайшее действие: инвентаризация игровых трасс, затем:

```powershell
py -3 scripts/new-iteration.py --from 001-car-viewer --name 002-track-viewer
```

Не запускать повторно при существующей 002. После копирования сразу заменить
унаследованный PLAN: он описывает завершённую 001, а не активную работу 002.

После создания 002 базовые команды (это план проверок, они ещё не выполнялись):

```powershell
. ./scripts/tool-env.ps1
cargo fmt --manifest-path iterations/002-track-viewer/Cargo.toml --all -- --check
cargo check --manifest-path iterations/002-track-viewer/Cargo.toml --target-dir local/builds/002-track-viewer/.cargo-target --locked --workspace
cargo test --manifest-path iterations/002-track-viewer/Cargo.toml --target-dir local/builds/002-track-viewer/.cargo-target --locked --workspace
. ./scripts/build.ps1 -Iteration 002-track-viewer -Config release -Target all
py -3 scripts/serve-web.py --iteration 002-track-viewer --port 8000
```

Перед сервером проверить, не занят ли порт viewer-ом 001; не останавливать чужой
процесс, выбрать свободный порт при необходимости. Track inspect/capture команды
внести после T02 вместе с согласованным CLI, не выдавать будущие флаги за существующие.
