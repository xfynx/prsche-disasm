# Заметки по реверс-инжинирингу nfs5.exe

В этом документе зафиксирована методология, ассемблерные листинги и математические выкладки, полученные в ходе исследования оригинального бинарника `Need for Speed: Porsche Unleashed` (`local/game/nfs5.exe`, версия 3.5 / патч 2019, база PE32 `0x00400000`, MSVC++ 6.0).

---

## 1. Контекст и предпосылки

Сторонние опенсорсные проекты (например, `OpenNFS/LibOpenNFS` и `CrpLib`) документируют форматы геометрии машин (`.crp`) и текстурных архивов (`.fsh`). Однако форматы топологии трасс (`.edg`, `.jnc`), динамических объектов окружения (`.scn`) и секций текстурирования (`.map`) в открытых источниках отсутствовали.

Для реализации корректной навигации, дорожной геометрии и расстановки декораций потребовалось исследовать оригинальный код движка в `nfs5.exe`.

### Характеристики исполняемого файла
- **Формат**: PE32 (x86, 32-bit little-endian).
- **Базовый адрес загрузки (ImageBase)**: `0x00400000` (ASLR отсутствует).
- **Смещение секции `.text`**: линейное отображение $\text{File Offset} = \text{VA} - 0x400000$.
- **Компилятор**: Microsoft Visual C++ 6.0 (активное использование оптимизаций целочисленного деления через умножение на взаимно-обратные константы).

---

## 2. Поиск точек входа (String Xrefs)

Поиск бинарных строковых литералов в секциях данных (`.rdata` / `.data`) выявил имена форматов:
- Строка `"%s.jnc"` находится по адресу VA `0x5d05e4`.
- Строка `".edg"` находится по адресу VA `0x5d05fc`.
- Строка `".map"` находится в окрестностях парсера INI по адресу VA `0x440ee0`.

Перекрёстные ссылки (xref) из секции кода `.text` привели к функциям-обработчикам:
- **`0x48789f`**: формирование пути к файлу развилок `sprintf(buf, "%s.jnc", track_name)` и передача в менеджер ресурсов `0x481080`.
- **`0x488090`**: подготовка буфера пути к файлу кромок полотна `sprintf(buf, "%s.edg", track_name)` и вызов функции чтения `0x487e80`.

## 3. Реверс формата `.jnc` (Junctions — развилки дорог)

### 3.1. Ассемблерный листинг функции проверки (VA `0x00481080`)

```x86asm
; ecx = указатель на объект TrackManager
; [esp + 0x18] = имя файла / дескриптор .jnc
0x00481080: sub     esp, 8
0x00481083: push    ebp
0x00481084: push    esi
0x00481085: push    edi
0x00481086: mov     edi, dword ptr [esp + 0x18]
0x0048108a: mov     ebp, ecx
0x0048108c: push    edi
0x0048108d: call    0x59ddd0                ; Получить размер файла в байтах
0x00481092: mov     ecx, eax                ; ecx = file_size
0x00481094: mov     eax, 0x38e38e39         ; Магическая константа деления на 36
0x00481099: mul     ecx                     ; edx:eax = file_size * 0x38e38e39
0x0048109b: mov     eax, dword ptr [ebp + 0x1c]
0x0048109e: mov     esi, edx                ; esi = старшие 32 бита произведения
0x004810a0: shr     esi, 3                  ; esi = esi >> 3 (деление на 8)
...
0x004810c0: cmp     esi, edx                ; Сравнение с ожидаемым числом развилок
0x004810c2: jne     0x481180                ; Несовпадение -> выход с ошибкой
...
; Чтение записей развилок:
0x00481103: add     ebx, 4                  ; Пропуск 4-байтного u32 index, переход к весам
0x00481106: mov     dword ptr [esp + 0x1c], ebx
0x0048110e: mov     ecx, dword ptr [edi + eax + 0x20]
```

### 3.2. Математика деления на 36 (`0x24`)

Компилятор MSVC оптимизирует беззнаковое деление на константу $D = 36$:
$$\frac{2^{35}}{36} = \frac{34359738368}{36} = 954437176.888\dots \approx 0x38E38E39$$

При выполнении:
1. `mul ecx` умножает размер файла $N$ на $0x38E38E39$, сохраняя результат в регистровой паре `edx:eax`.
2. Регистр `edx` содержит $\lfloor (N \times 0x38E38E39) / 2^{32} \rfloor$.
3. Инструкция `shr esi, 3` сдвигает значение вправо ещё на 3 бита ($2^3 = 8$).
4. Итоговый делитель: $2^{32} \times 2^3 / 0x38E38E39 = 2^{35} / 0x38E38E39 = 36.000000003 \approx 36$.

**Вывод**: размер каждой записи файла `.jnc` составляет **ровно 36 байт**.

### 3.3. Структура записи `.jnc` (36 байт)
| Смещение | Тип | Имя | Описание |
|---|---|---|---|
| `0x00` | `u32` | `index` | 0-based порядковый номер развилки трассы |
| `0x04` | `f32[8]` | `weights` | До 8 вероятностей/весов выбора направления на развилке для ИИ |

## 4. Реверс формата `.edg` (Road Edges — кромки полотна дороги)

### 4.1. Ассемблерный листинг загрузчика (VA `0x00487e80`)

```x86asm
0x00487e80: sub     esp, 0x34
0x00487e83: mov     eax, dword ptr [esp + 0x38]
0x00487e87: push    edi
0x00487e88: push    0
0x00487e8a: push    eax
0x00487e8b: call    0x59da80                ; Открыть файл .edg
0x00487e90: mov     edi, eax                ; edi = файловый дескриптор / буфер
...
0x00487ea4: push    edi
0x00487ea5: call    0x556640                ; Получить размер файла в байтах
0x00487eaa: mov     ecx, eax                ; ecx = file_size
0x00487eac: mov     eax, 0x24924925         ; Магический множитель Granlund-Montgomery
0x00487eb1: sub     ecx, 4                  ; Вычитаем 4 байта заголовка!
0x00487eb4: add     esp, 4
0x00487eb7: mul     ecx                     ; edx:eax = (file_size - 4) * 0x24924925
0x00487eb9: sub     ecx, edx
0x00487ebb: shr     ecx, 1
0x00487ebd: add     ecx, edx
0x00487ebf: shr     ecx, 4                  ; Итоговое деление на 28 (0x1c)
0x00487ec2: je      0x48807c                ; Если записей 0 -> завершить
...
; Цикл по записям кромок:
0x00487ecb: lea     esi, [edi + 0xc]        ; Указатель на первую запись со смещением
0x00487ece: mov     dword ptr [esp + 0x18], esi
0x00487ed2: mov     dword ptr [esp + 0x1c], ecx ; ecx = количество отрезков
; Чтение 6 чисел с плавающей точкой (p1 и p2 по 12 байт):
0x00487ed6: mov     ecx, dword ptr [esi - 4] ; p1.x
0x00487ed9: mov     edx, dword ptr [esi]     ; p1.y
0x00487edb: mov     eax, dword ptr [esi + 4] ; p1.z
0x00487ede: mov     dword ptr [esp + 0x24], ecx
0x00487ee2: mov     ecx, dword ptr [esi + 8] ; p2.x
0x00487ee5: mov     dword ptr [esp + 0x28], edx ; p2.y
0x00487ee9: mov     edx, dword ptr [esi + 0xc] ; p2.z
...
; Чтение флага типа поверхности:
0x00487f0d: movzx   cx, byte ptr [esi - 8]  ; cx = байт флага (offset +4 от начала записи)
0x00487f12: lea     edx, [esp + 0x24]       ; edx = массив координат [p1, p2]
0x00487f16: push    ecx                     ; Аргумент 2: flags
0x00487f17: push    edx                     ; Аргумент 1: points pointer
0x00487f18: mov     ecx, eax                ; this
0x00487f1a: call    0x485100                ; Конструктор C++ объекта EdgeSegment
```

### 4.2. Математика деления на 28 (`0x1c`) по схеме Гранлунда-Монтгомери

Деление на 28 реализовано стандартным компиляторным шаблоном для нестепенных нечётных множителей:
$$\frac{2^{34}}{28} = \frac{17179869184}{28} = 613566756.57\dots \approx 0x24924925$$

Последовательность инструкций:
```x86asm
mul     ecx             ; edx = (N * 0x24924925) >> 32
sub     ecx, edx        ; ecx = N - edx
shr     ecx, 1          ; ecx = (N - edx) / 2
add     ecx, edx        ; ecx = (N + edx) / 2
shr     ecx, 4          ; ecx = ecx >> 4 (деление на 16)
```
Результирующее значение строго вычисляет целочисленное $\lfloor (N - 4) / 28 \rfloor$.

### 4.3. Раскладка записи `.edg` (28 байт)
Каждая запись следует сразу за 4-байтным файловым заголовком:
| Смещение в записи | Размер | Тип | Имя | Назначение |
|---|---|---|---|---|
| `0x00` | 1 байт | `u8` | `flags` | Тип поверхности/ограничения (`0x00`=асфальт, `0x10`=стена, `0x20`=поребрик/трава) |
| `0x01` | 3 байта | `u8[3]` | `padding` | Не используются кодом загрузчика (выравнивание) |
| `0x04` | 12 байт | `f32[3]` | `p1` | 3D-координата начала отрезка `[X, Y, Z]` (в метрах) |
| `0x10` | 12 байт | `f32[3]` | `p2` | 3D-координата конца отрезка `[X, Y, Z]` (в метрах) |

## 5. Конструктор пространственных сегментов дорог (VA `0x00485100`)

В функции `0x00485100` движок инициализирует экземпляр C++ класса ребра полотна:
```x86asm
0x00485100: mov     eax, dword ptr [esp + 4]
0x00485104: sub     esp, 0x18
0x00485107: lea     edx, [ecx + 0xc]
0x0048510a: mov     dword ptr [ecx], 0x5b484c   ; Запись vtable pointer класса
...
; Вычисление AABB (Axis-Aligned Bounding Box) через FPU для ускорения проверок столкновений:
0x0048514e: fld     dword ptr [edx]         ; Загрузка p1.x
0x00485150: fcomp   dword ptr [esi]         ; Сравнение с p2.x
0x00485152: fnstsw  ax                      ; Сохранение статуса FPU в регистр AX
0x00485154: test    ah, 1
0x00485157: je      0x48515d
0x00485159: fld     dword ptr [edx]         ; min_x = p1.x
0x0048515b: jmp     0x48515f
0x0048515d: fld     dword ptr [esi]         ; min_x = p2.x
...
```
- Таблица виртуальных методов (`vtable`) класса сегментов дорог расположена по адресу **`0x005b484c`**.
- Для каждого сегмента движок на лету вычисляет пространственный ограничивающий объём (`AABB`), используемый физическим ядром для коллизий и возврата машины на полотно.
