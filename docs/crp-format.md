# Форматы CRP, FSH и TPG

Эта заметка описывает только то, что использует просмотрщик первой итерации.
Источник фактов: локальная проверка `local/research/inspect_crp.py`, декодированные
`356a`/`356b` и справочный `local/references/LibOpenNFS/lib/CrpLib`. Исходные игровые
файлы остаются в `local/game` и в Git не добавляются.

## CRP

`*.crp` начинается либо с RefPack (`10 FB`), либо уже содержит распакованные данные.
У RefPack после сигнатуры расположен размер результата в трёх big-endian байтах. Для
проверенной копии игры: `356a` распаковывается из 1 640 460 в 3 764 224 байта (181
статья, 87 misc-записей), `356b` — из 1 577 631 в 3 346 432 байта (152, 72).

Распакованный CRP начинается с little-endian `Car ` (в байтах `20 72 61 43`). Поле
по смещению `0x04` содержит число статей в старших 27 битах, `0x08` — число misc
записей, `0x0c * 16` — начало таблицы. Запись таблицы занимает 16 байт:

- ID; у двухбуквенных ID младшие 16 бит — индекс и установлен флаг `1`;
- длина в старших 24 битах следующего слова;
- count;
- относительное смещение. Для контейнера нулевой длины оно измеряется в блоках по
  16 байт; для данных — в байтах.

Статья `Arti` содержит `Base`, `Name`, `vt`, `nm`, `uv`, `tr` и `pr`. Для
`vt`/`nm`/`uv` индекс имеет level в младшем ниббле, номер анимации выше него и флаг
повреждения в бите 15. `pr` использует другой индекс: level в старших четырёх битах,
номер части — в младших 12.

Для parked-car сцены сначала выбирается TPG `[style1]` (если отсутствует — type0).
Пары geometryN/typeN задают `Base.GeomIndex/TypeIndex`, textureN/typeN задают
независимый набор текстурных вариантов. Неуказанные группы имеют type0. Затем
для всей сцены берётся минимальный ненулевой Level среди выбранных статей.
Статья должна иметь этот Level или общий level0; `vt`/`nm`/`uv` выбираются по
этому index, `pr` — по `pr.index >> 12`. Driver исключается по биту `0x80`
в BaseInfo.LevelIndex. Имена In/Out не участвуют в выборе.
Материал `mt` хранит номер страницы TPG как
little-endian `u32` по смещению `0x28`; это нулевой индекс страницы, а не номер `sf`.
Матрица `tr` содержит 16 `f32` в column-major порядке и описывает размещение
части. В текущем загрузчике вершины масштабируются из единиц CRP `/5`, а из
`tr` используется только перенос `mat[3]` (также `/5`); затем и вершина, и перенос
вместе однократно отражаются по Z при переходе к Scene. Поворотная часть матрицы не
применяется повторно к каждой вершине или нормали. Это соответствует
закреплённой реализации LibOpenNFS и сохраняет относительное размещение частей.

Источник: `local/references/LibOpenNFS/lib/CrpLib/Common.h` (`tLevelMask`,
`LEVELINDEX_*`) и `Entry.cpp` (`GetPartEntry`, `GetDataEntry`),
`local/references/LibOpenNFS/NFS5/NFS5Loader.cpp` (цикл `GetLevel(v)`). Данные:
`local/research/356a.json`, `356b.json`; в них `TreadFront`/`TreadRear` имеют
первый `tLevelMask.Level == 4`. Старое правило «первый mask каждой статьи»
неверно смешивало гоночный Tread4 с frontend1. Это исправлено в run008.
Точное runtime-переключение дверей/капота остаётся непроверенным.

`pr` содержит таблицу каналов и строк индексов. Каналы `0`, `1`, `2` означают
вершины, нормали и UV. Индексы в данных — байтовые; поле Offset канала задаёт базовый
индекс в соответствующем массиве (Offset/16 для vt/nm, Offset/8 для uv).
`IndexRowRef` выбирает строку `tPartIndex`; значение `0xffff` обозначает
последовательный канал (индекс i+base), а не испорченную ссылку. Такие каналы
есть у 928/930/eas5/gt1; полностью неиндексированные части nd=0 тоже допустимы.
Тесты покрывают смешанные indexed/sequential каналы и ненулевые Offset.
Геометрия уже содержит обе стороны машины, поэтому
загрузчик не создаёт зеркальную копию.

При отражении CRP→Scene по Z loader отражает позиции и нормали, но не меняет порядок
индексов. Данные `examples/audit_scene.rs` для 356b до этого исправления дали
`aligned=107`, `opposed=2984`, `degenerate=0`: исходный CRP winding в основном CW
относительно supplied normal, а отражение без swap делает его согласованным. Это факт
локального аудита; правило требует повторной проверки на corpus и не является выводом
о runtime-culling оригинальной игры.

`Material.alpha_mode` определяется без номера страницы: render method `CarExt`,
`CarExtEnv` используют Mask для alpha0 и непрозрачные промежуточные значения
(разметка окраски), `CarInt` пока Opaque;
для остальных loader использует `bpp` целевой `[tpageN.details]` и alpha выбранного
атласа. `1555` с alpha 0 — Mask/cutoff 0, `4444` — Blend, иначе бинарный alpha даёт
Mask, дробный — Blend. Флаг `mt +0x0c` документирован CrpLib только как cull (`0x20`)
и не участвует в alpha-классификации. Факт EAS1: `WheelShadow*` использует
`CarWheel` с `shadow.fsh` (4444, alpha 0..199), а wheel tiles имеют 1555/0..255.
В run008 прямоугольники shadow/cutout колёс трафика устранены. Run009 проверяет
exterior Mask и тестовую окраску: alpha255 сохраняет фары/хром, промежуточный
alpha окрашивается. Полный CLR и runtime-смысл уровней alpha пока не восстановлены.

FSH tile-фильтры fileN.tile выбираются по geometryK или textureK и typeK того же
style1; альтернативные пары объединяются OR, словари geometry/texture не смешиваются.
Пример: 928/944 file3.whf1 требует texture13/type1; жёсткий type0 оставлял колёса пустыми.

## Совпадающие поверхности и смещение глубины

Run010: у 356b Body и Light1 пересекают контрольный луч при одинаковом
`t=0.919246852`. `mt4` и `mt12` имеют одинаковые render method, TPG и cull;
различия данных: signed `mt+0x114` = 0/-3, `mt+0x134` = 0/2.
`pr.TransInfo` = 0/0x200. `tPartInfo.Level` у обоих равен 1, RMOffs совпадают,
поэтому несовпадение каналов не объясняет исчезновение фар.

Viewer передаёт signed `mt+0x114` в constant depth bias GPU-пайплайна.
В 1578 материалах корпуса значения: 0 (987), 1 (65), 3 (73), -10 (75),
-3 (288), 5 (28), -2 (34), -1 (28). Геометрия не смещается, имена частей
не проверяются. Synthetic `coplanar_material_bias_gpu` доказывает независимость
видимости coplanar-детали от порядка частей. Сортировка по material ID помогала
как контрольный опыт, но не является рабочим исправлением.

Это интерпретация поля, подтверждённая данными и GPU-опытом, не доказательство
точных единиц/алгоритма смещения глубины оригинального renderer.
Команда численного аудита (из корня, после tool-env):

```powershell
cargo run --manifest-path iterations/001-car-viewer/Cargo.toml --target-dir local/builds/001-car-viewer/.cargo-target -p nfs-assets --example audit_scene -- local/game/GameData/CarModel 356b --ray-light1
```

## FSH и TPG

FSH имеет `SHPI`, длину архива и каталог из восьмибайтовых записей. Нужные встроенные
и общие FSH используют формат `0x7d`: BGRA32, который преобразуется в RGBA. Для
совместимости также читаются BGR24 `0x7f` и индексированный `0x7b` с палитрами.
Границы читаются по длине самого FSH, а не по буферу окружающего CRP.

TPG — INI. Страницы `[tpageN.details]` нумеруются с 1, тогда как `mt.tpg` с 0.
`[fileN.details].tpage` определяет целевую страницу атласа. Положение тайла находится
в заголовке FSH: x/y по смещениям `+0x0c/+0x0e`; TPG добавляет `offsetx/offsety`.
`sf` в CRP сопоставляется с `fileN` как `sf.index == N - 1`. В `356a` и `356b` это
покрывает file 1–4 и 8; оставшиеся нужные пакеты берутся из общего каталога.

Размещение — растровая операция с клиппингом по границам TPG-страницы, а не
требование полного попадания прямоугольника. Это подтверждено локальными данными:
`944`/`file2.full` имеет `x=209`, ширину 48 и страницу шириной 256, то есть один
пиксель выходит справа. `eas2`/`file1.top` записывает левую координату как
`0x0fff`, а `eas3`/`file1.fro` верхнюю как `0xffff`; оба обозначают origin `-1`
и сохраняют пересечение с атласом. Loader принимает эти два NFS5-варианта
кодирования `-1`, применяет TPG offset, поворот и затем копирует только пиксели в
границах страницы. Тайлу без единого пересечения и несогласованному размеру
пиксельного буфера по-прежнему соответствует ошибка.

Источник поля x/y: `local/references/LibOpenNFS/Shared/FSH/FshTypes.h` (16-byte
`FshEntryHeader`, четыре `misc` u16) и описание общего FSH layout:
<https://modthesims.info/wiki.php?title=FSH>. Значения `944`/`eas2`/`eas3` получены
`local/research/inspect_crp.py` из `local/game/GameData/CarModel`. Гипотеза:
`0x0fff` — 12-битное, а `0xffff` — 16-битное представление того же border origin
`-1`; это согласуется с непустым пересечением и плотной упаковкой тайлов, но ещё не
сверено с машинным кодом оригинала.

Для припаркованной машины обязательны следующие общие файлы, если они не встроены:
`INTGLASS.FSH`, `Shadow.fsh`, `Cabrio.fsh`. Suit и head (`global=3/4`) намеренно не
запрашиваются: водитель не входит в эту сцену. Ошибка загрузчика перечисляет все
отсутствующие общие FSH одним сообщением, чтобы native и WASM интерфейсы могли запросить
их за один выбор файлов.

## Неподтверждённое

CLR-маска перекраски кузова и точное правило зеркальной TPG-страницы ещё не подтверждены
оригинальным кодом. Альфа кузова со значениями 77/204 пока не меняет выбор материала;
рендерер сохраняет её как непрозрачную до отдельного исследования.
